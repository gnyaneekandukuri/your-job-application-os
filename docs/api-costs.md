# Local API costs and bounded evidence retrieval

The API costs page is local and requires no LangSmith subscription or external telemetry. It reads stored call ledgers; viewing or refreshing it does not make model calls. Filter by browser-local calendar days and provider. New whole-role extraction, retrieval embeddings, evidence batches and pursuit recommendations are attributed to their job and stage. Legacy calls and other flows without attribution are explicitly listed as unattributed. Failed calls with unknown usage are not counted as zero-dollar successes. Diagnostic calls outside the app ledger and other apps' usage are excluded. Jev totals cover cached successful discovery classifications; standalone benchmark usage is separate.

New GPT-6 Sol cost estimates use returned input, output, cache-read and cache-write counts at published standard rates ($2/$10/$0.20/$2.50 per million respectively). They are estimates, not provider invoices. Unknown model overrides carry an unverified estimate label. Existing historical costs are retained as conservative estimates. No new spending cap has been introduced.

Whole-role evidence analysis now uses each requirement's interpretation and original JD quote as a retrieval query. Query embeddings are cached by exact text. Existing raw story embeddings and BM25 are combined with reciprocal rank fusion locally; no paid generative reranker is added. Four top original passages per requirement are merged in round-robin order for each four-requirement batch, deduplicated, and bounded to 48,000 serialized UTF-8 bytes of evidence. This replaces repeatedly sending all prepared stories. Vectors and generated summaries are excluded from model evidence. Exact quote validation and all fact/conflict rules remain enforced. Missing retrieved evidence is explicitly not proof of absent experience; clarification remains available.

Each selection stores a retrieval-version manifest in the private cache. Existing completed reports are preserved, not automatically rescored. New batch cache keys include the retrieval version. Context limits stop rather than falling back to the full corpus. An oversized individual passage may need rechunking. Top-k retrieval can miss relevant evidence, so the UI review and clarification loop remains important. Mocked tests verify selection, bounds, original text, cache rates, attribution and migrations; a live quality comparison on representative jobs is still needed before asserting unchanged assessment quality or a specific cost saving.

On the personal library checked October 2, 2026, the previous evidence array was 191,418 bytes across 86 passages. The 48,000-byte cap reduces that component by at least 74.9%; it does not promise the same reduction in the full bill, which also includes instructions, rules and generated output.
